# 架构

`runbook-core` 拥有所有持久化、校验和命令拼接逻辑，CLI 和 Tauri IPC 只是适配层。服务请求是带 `op` 的强类型枚举，`schema` 直接从实际 Rust 类型生成 JSON Schema。

数据库按项目存储聚合文档，每次写入在 `BEGIN IMMEDIATE` 事务中重新读取当前文档、检查版本、修改目标对象后提交。GUI 不允许提交整库替换。CLI 与 GUI 不需要互相启动或依赖常驻服务。

终端属于桌面进程的会话管理器。一个会话对应一个真实 PTY 和 Shell 进程，前端通过会话 ID 读写；网页切换后可以重新附着。输出按递增序号存入最多 2 MiB 的环形缓冲区，前端每 150ms 拉取增量，发生截断会明确提示。输出以 Base64 字节传输，交给 xterm 的 UTF-8 解码器处理跨块的中文字符。

工作台为每个终端标签缓存独立的 xterm、输出序号和视口。切换标签复用已有视图，仅补充尚未读取的输出；首次附着和后台补充输出在显示前批量写入，避免逐块滚动重放。关闭标签时销毁对应视图。浅色／深色主题使用共享 CSS 变量并保存到本机 WebView 存储，同时更新缓存终端的配色和原生窗口主题，不清空输出。

Windows 通过 ConPTY 启动 PowerShell。每个会话附加独立 Job Object，关闭会话或应用时清理进程树；命令根进程结束时也清理其后代，避免孤立服务。先收集根进程退出码，再关闭 PTY 并排空输出，最后发布结束状态。新终端使用 `-NoProfile`，不会加载个人 PowerShell profile。

桌面通过标签页管理常驻 PowerShell。执行命令库中的命令时，`terminal_execute` 校验项目、命令版本、参数、提示符就绪状态和未提交输入，再向当前会话发送 dot-source 命令块，保留目录、变量和函数。提示符输出带随机会话标识的内部帧，Rust 增量解析并从可见输出剥离，记录本次执行的结束状态、退出码与当前目录；Shell 自身的进程退出与单次命令结束分别记录。停止先发送 Ctrl+C，不自动销毁标签页；需要时用户可强制结束或关闭标签。CLI `command run` 继续使用独立的一次性 Shell 与超时控制。

切换项目不会停止会话；归档或删除项目时，桌面会在数据同步时关闭该项目的会话，避免留下无法再访问的后台进程。关闭应用会结束全部会话。会话和终端输出不跨应用重启恢复。

配置保存在数据库；终端输出保存在应用内存，不写入数据库。项目路径在创建/编辑和启动会话时验证，不会自动创建、移动或删除用户目录。

关闭标签页或应用时，同步关闭输入端和 PTY 主端，避免只终止 Shell 后依赖后台等待线程释放控制台。

默认使用系统 WebView2，不捆绑 Chromium 或 Node.js。终端资源随应用本地打包，不访问 CDN。前端依赖 Tauri IPC 连接本机服务；单独在浏览器中打开 HTML 不具备原生执行功能。

## 检查

Rust 测试覆盖：事务回滚、并发创建、乐观锁冲突、严格 JSON 输入、路径去重、参数引用、真实 PTY 的中文/目录/退出码、交互输入/缩放/强制停止，以及独立 CLI 的 JSON 协议与超时。
